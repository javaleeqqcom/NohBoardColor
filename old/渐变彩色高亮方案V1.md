# 渐变彩色高亮方案 V1（归档废稿）

> - 归档状态：**废稿，不计划实施**
> - 文档版本：Draft 0.1（随 NohBoardColor v1.4.0 归档）
> - 原始记录日期：2026-08-03
> - 最后标注日期：2026-08-09
> - 废弃原因：经讨论，小朋友难以通过彩色轮盘准确判断按钮先后顺序。当前采用更简单的按键渐暗特效；本文仅保留为历史设计记录。

可以把两种效果统一成一套“按键余晖引擎”，通过设置切换：

* 固定余晖：所有按键使用同一种高亮色，适合教学。
* 色相轮盘：每次新按键沿色环前进，输入顺序一目了然。
* 彩色余晖：轮盘颜色与渐隐同时启用，视觉效果最好。

我建议先实现“固定余晖”，稳定后再开启色相轮盘。

## 一、推荐效果参数

| 阶段    |      时长 | 显示效果        |
| ----- | ------: | ----------- |
| 按住    |      不限 | 100% 高亮     |
| 松开后停留 |  250 ms | 保持100%亮度    |
| 渐隐    | 1250 ms | 平滑降低至0%     |
| 总可见时间 | 1500 ms | 足够小朋友抬头找到按键 |

渐隐不要采用生硬的线性变化，建议使用平滑曲线：

```csharp
double x = elapsedFadeMs / fadeDurationMs; // 0~1
double intensity = 1 - (3 * x * x - 2 * x * x * x);
```

效果是：刚松开时下降较慢，最后自然熄灭。

## 二、色相轮盘规则

每次发生一次真正的“新按下”，色相前进固定角度：

```csharp
hue = (hue + 43) % 360;
```

例如：

```text
A：红色
B：橙黄色
C：绿色
D：青色
E：蓝色
F：紫色
```

选择 `43°` 而不是按照七色硬切，可以避免连续按键颜色过于相近，也不会很快形成机械重复。

需要特别处理：

* Windows 长按产生的自动重复不算新按键，颜色不能一直跳变。
* 判断依据必须是“未按下 → 按下”的状态变化。
* 同一个键在余晖尚未消失时再次按下，应立即恢复100%亮度，并获得新的轮盘颜色。
* 同时按下多个键时，按照检测到的先后顺序分配颜色。

## 三、数据结构

建议新增：

```text
NohBoard
└─ NohBoard
   └─ Keyboard
      └─ Effects
         ├─ KeyEffectMode.cs
         ├─ KeyVisualState.cs
         ├─ KeyEffectController.cs
         └─ HsvColor.cs
```

单个按键状态：

```csharp
internal sealed class KeyVisualState
{
    public bool WasPressed { get; set; }
    public bool IsPressed { get; set; }

    public long PressedAt { get; set; }
    public long ReleasedAt { get; set; }

    public Color EffectColor { get; set; }
}
```

状态建议按照键盘元素的 `Id` 保存：

```csharp
Dictionary<int, KeyVisualState> states;
```

不要只按照 KeyCode 保存，因为 NohBoard 支持组合键定义，一个元素可能包含多个 KeyCode。当前源码也是先根据元素的全部 `KeyCodes` 判断它是否按下。[MainForm.cs 的按键判断与绘制](https://github.com/ThoNohT/NohBoard/blob/master/NohBoard/NohBoard/Forms/MainForm.cs)

## 四、渲染方案

NohBoard 当前的工作方式是：

1. 预先缓存所有未按下按键的背景。
2. 每次绘制先贴上缓存背景。
3. 只重新绘制当前处于按下状态的按键。
4. 按键一松开，便不再单独绘制，所以立即恢复普通颜色。

因此，余晖的关键不是修改键盘钩子，而是让“已经松开但余晖尚未结束”的按键继续参加绘制。

建议的绘制顺序：

```text
缓存的普通键盘
→ 松开后的彩色余晖
→ 当前按住的完整高亮
→ 文字和边框
```

现有 `KeyboardKeyDefinition.Render()` 只接收一个 `bool pressed`，在普通样式和按下样式之间二选一。[KeyboardKeyDefinition.cs](https://github.com/ThoNohT/NohBoard/blob/master/NohBoard/NohBoard/Keyboard/ElementDefinitions/KeyboardKeyDefinition.cs)

建议新增：

```csharp
public void RenderEffect(
    Graphics graphics,
    Color color,
    float intensity,
    bool shift,
    bool capsLock)
```

第一版采用半透明色层覆盖普通按键：

```csharp
int alpha = (int)(255 * intensity);

using var brush = new SolidBrush(
    Color.FromArgb(alpha, color));

graphics.FillPolygon(
    brush,
    Boundaries.ConvertAll<Point>(p => p).ToArray());
```

这样不需要每帧修改、清空现有的画刷缓存，也不会破坏已有键盘样式。

注意：`Brush`、`Pen` 必须及时 `Dispose`，否则连续动画可能耗尽 GDI 对象。

## 五、必须修改刷新条件

这是最容易漏掉的地方。

当前更新计时器只有在键盘或鼠标状态变化时才刷新：

```csharp
if (KeyboardState.Updated || MouseState.Updated)
    this.Refresh();
```

但按键松开后，键盘状态只变化一次；后面的渐隐阶段没有新的键盘事件，画面将停在某一亮度。

应改为：

```csharp
if (KeyboardState.Updated
    || MouseState.Updated
    || keyEffectController.HasActiveEffects)
{
    this.Invalidate();
}
```

只要还有余晖，窗口就持续刷新；全部熄灭后自动停止刷新，不会让程序一直占用 CPU。现有刷新入口位于 `MainForm.UpdateTimer_Tick()`。[MainForm.cs 的刷新计时器](https://github.com/ThoNohT/NohBoard/blob/master/NohBoard/NohBoard/Forms/MainForm.cs)

## 六、推荐设置项

第一版可以先写入全局配置，不必急着制作复杂设置窗口：

```csharp
EffectMode = KeyEffectMode.Afterglow;
EffectHoldMilliseconds = 250;
EffectFadeMilliseconds = 1250;

FixedEffectColor = Color.FromArgb(255, 210, 40);

HueStart = 0;
HueStep = 43;
HueSaturation = 0.80;
HueBrightness = 1.00;
```

模式枚举：

```csharp
public enum KeyEffectMode
{
    Off,
    FixedAfterglow,
    HueWheel,
    HueWheelAfterglow
}
```

其中：

* `Off`：完全保持原版。
* `FixedAfterglow`：固定颜色渐隐，推荐教学使用。
* `HueWheel`：按键按顺序换色，但松开即灭。
* `HueWheelAfterglow`：按顺序换色并渐隐，推荐展示使用。

## 八、验收测试

至少测试这些情况：

* 快速短按：按键仍显示约1.5秒。
* 长按：一直保持全亮，松开后才开始计时。
* 连续输入 `hello`：每个按键独立渐隐。
* 快速重复按 `A`：每次重新点亮，不出现闪黑。
* 长按触发系统自动重复：颜色不疯狂轮换。
* `Shift+A`、`Ctrl+C`：组合键显示正确。
* Caps Lock：文字切换不受余晖影响。
* 切换键盘模型：旧模型的余晖状态全部清空。
* 关闭效果：表现与原版完全一致。

最终推荐默认采用“黄色固定余晖：停留250 ms，渐隐1250 ms”；彩色色相轮盘作为可选效果。这样最符合你让打字较慢的小朋友抬头寻找按键的教学需求。
